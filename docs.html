ENCRYPTION FORMATS / two dialects

Adyen has two generations of client-side encryption. This API speaks both. Pick jwe for modern Adyen v6 integrations, cse for legacy adyenjs checkouts.

JWE — v6 (modern)
  • Header — {"cty":"application/json","alg":"RSA-OAEP-256","enc":"A256GCM","version":"1"}
  • CEK — 256-bit AES key, wrapped with RSA-OAEP-256
  • Body — AES-256-GCM, 12-byte IV, 16-byte tag
  • Payload — JSON {"<field>":"<value>","generationtime":"..."}
  • Output — 5-part compact JWE
CSE — legacy (v1/v2)
  • Prefix — adyenjs_0_1_25$
  • CEK — 256-bit AES key, wrapped with RSA PKCS#1 v1.5
  • Body — AES-256-CCM, 12-byte nonce, 8-byte tag
  • Payload — <field>:<value>\ngenerationtime:...
  • Output — adyenjs_0_1_25$ + base64 blob
FIELDS: both modes encrypt the same four fields → number, expiryMonth, expiryYear, cvc.
02

GETTING A KEY / exp|mod

Every /encode call needs an Adyen public key in exponent|modulus hex form. Two ways to obtain one — feed a checkout page to /extract, or a clientKey to /pubkey.

CHECKOUT HTML
→
/extract
→
clientKey
→
/pubkey
→
publicKey (exp|mod)
→
/encode
# 1. pull the clientKey + (sometimes) the publicKey straight off the page
curl -s -X POST https://adyene.onrender.com/extract \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://checkout.example.com/pay"}'

# 2. if the page didn't expose the key directly, resolve it from the clientKey
curl -s "https://adyene.onrender.com/pubkey?clientKey=live_XXXX&env=live"

CARD INPUT / one string

Cards are passed as a single pipe-delimited string. Year accepts 2 or 4 digits.

CC|MM|YY|CVV      // 2-digit year
CC|MM|YYYY|CVV    // 4-digit year
4111111111111111|12|28|737

04

/encode

Encrypt a card against an Adyen public key. Returns the four encrypted fields ready to drop into a payment request.

GET · POST/encode
Parameters
ParamTypeNotes
key REQUIREDstringAdyen public key, format exponent|modulus (hex)
card REQUIREDstringCC|MM|YY|CVV or CC|MM|YYYY|CVV
mode OPTIONALstringjwe (default) or cse
Request — GET (JWE)
curl -s "https://adyene.onrender.com/encode?key=10001|DBF7...&card=4111111111111111|12|28|737&mode=jwe"
Request — POST (CSE)
curl -s -X POST https://adyene.onrender.com/encode \
  -H 'Content-Type: application/json' \
  -d '{
    "key": "10001|DBF7...",
    "card": "4111111111111111|12|2028|737",
    "mode": "cse"
  }'
Response
{
  "success": true,
  "mode": "cse",
  "brand": "visa",
  "data": {
    "encryptedCardNumber": "adyenjs_0_1_25$Vl3aa2d2...",
    "encryptedExpiryMonth": "adyenjs_0_1_25$k9c...",
    "encryptedExpiryYear": "adyenjs_0_1_25$b2m...",
    "encryptedSecurityCode": "adyenjs_0_1_25$Q7f..."
  }
}

/parse

Map a raw Adyen payment response to a clean decline_code. Handles resultCode, refusalReason, refusalReasonCode, and 3DS redirects.

POST/parse
Request
curl -s -X POST https://adyene.onrender.com/parse \
  -H 'Content-Type: application/json' \
  -d '{
    "resultCode": "Refused",
    "refusalReason": "Not enough balance",
    "refusalReasonCode": "2",
    "pspReference": "P123456789"
  }'
Response
{
  "success": true,
  "data": {
    "success": false,
    "decline_code": "insufficient_funds",
    "error": "Not enough balance (2)",
    "is_live": true,
    "psp": "P123456789"
  }
}
